Dice Roll & Guessing Game

โปรแกรมทอยลูกเต๋า

A desktop GUI application built in Java Swing. Players register or sign in through a custom borderless login window, pick from three dice modes with 6 to 999 sides—rolling one die, rolling two dice with a total, or guessing which hidden die rolled higher—and review past rolls saved to a text log.

Two packages, two visual styles

How the app is split

Default package · src/
  • frmLoginMain entry point. Borderless teal & cream window that reads src/user.txt and opens the main menu.
  • frmRegisterMatching borderless form that assigns the next numeric ID and appends a CSV row to src/user.txt.
  • Account & interfaceInfoHolds username and displayname on a shared static Account acc object.
  • tblUserAn earlier user-directory table screen with a LOGOUT button, kept in src/ but unused in the final flow.
Main package · src/Main/
  • DiceRollMainThai main menu (โปรแกรมทอยลูกเต๋า) that opens each mode as a modal JDialog.
  • OneDieRolls one custom die (6–999 sides) and logs the number.
  • TwoDiceRolls two custom dice, displays each face plus their sum, and logs the equation.
  • HigherDiceRolls two dice face-down, asks you to guess Left (ซ้าย) or Right (ขวา), and scores Win, Loss or Draw.
  • HistoryLoads src/Main/HistoryLog.txt into a 3-column JTable.
Original Java Swing GUI

Screen by screen

Every screenshot below was captured directly from the compiled Java Swing classes running under the Nimbus Look & Feel, using the project's own user.txt and HistoryLog.txt files.

  1. Default package · frmLogin.java

    Log in (or jump to Register)

    frmLogin calls setUndecorated(true) to remove the Windows title bar and draws its own teal (#00CCCC) and pale-yellow (#FFFFCC) header, PNG icons, and a top-right close button. Pressing Enter triggers btnLogin via getRootPane().setDefaultButton(btnLogin).

  2. Main · DiceRollMain.java

    Choose a dice mode

    After login, frmLogin disposes itself and opens DiceRollMain. Unlike the login screens, the game screens keep standard window borders and switch to Thai labels. Each game button opens a modal JDialog centered over the menu.

  3. Main · OneDie.java & TwoDice.java

    Roll one or two custom-sided dice

    Both dialogs check that the side count is an integer between 6 and 999, update the shared DieInfo.DICE instance, display the roll in 60pt Tahoma inside bordered white panels, change the button text from ทอย! to ทอยอีกครั้ง, and append a semicolon-separated line to HistoryLog.txt.

  4. Main · HigherDice.java

    Roll hidden dice, then guess Left or Right

    Pressing ทอย! rolls both dice behind the scenes with DICE.set2DiceRoll(), blanks both number boxes, disables the roll button, and reveals ซ้าย (Left) and ขวา (Right). Picking a side reveals both numbers, announces Win, Loss, or Draw, and writes (d1:d2) Win/Loss/Draw to HistoryLog.txt.

  5. Main · History.java

    Inspect the roll history

    History reads every line of src/Main/HistoryLog.txt with a Scanner, splits on ;, and adds rows to a 3-column JTable (Username, Type, Result).

  6. Unused screen · tblUser.java

    Bonus: the leftover user table window

    Still sitting in src/ is tblUser.java: a working JFrame that greets "Welcome " + acc.getDisplayname(), loads src/user.txt into a read-only JTable (hiding the 4th password column), and logs back out to frmLogin. Once frmLogin was wired straight to DiceRollMain, nothing opened this window anymore.

Inside the code

    
Key parts

    

      

        
Rolling custom-sided dice (Main/Dice.java)

        
Dice supports both one-off random rolls (used by OneDie and TwoDice) and storing a hidden pair ahead of time so HigherDice can compare them when the player clicks Left or Right.


public void set2DiceRoll() {
    this.dieRoll1 = (int) (Math.random() * (this.dieSide - 1 + 1) + 1);
    this.dieRoll2 = (int) (Math.random() * (this.dieSide - 1 + 1) + 1);
}

public int getRandomDieRoll() {
    return (int) (Math.random() * (this.dieSide - 1 + 1) + 1);
}

      

      

        
Locking the roll button until the player guesses (Main/HigherDice.java)

        
Two small helper methods flip the dialog between "waiting for a Left/Right guess" and "showing the result".


public void setGuessBtn() {
    btnLeft.setVisible(true);
    btnRight.setVisible(true);
    btnRoll.setEnabled(false);
}

public void setDiceResult() {
    btnLeft.setVisible(false);
    btnRight.setVisible(false);
    btnRoll.setEnabled(true);
    btnRoll.setText("ทอยอีกครั้ง");
}

      

      

        
Appending rolls and loading the history table (OneDie.java & History.java)

        
Each game dialog appends one semicolon-delimited line to HistoryLog.txt; History splits each line back into a 3-column DefaultTableModel row.


// OneDie.java — appending a roll
BufferedWriter writer = new BufferedWriter(new FileWriter(filename, true));

// History.java — populating the JTable
Scanner sc = new Scanner(myFile);
while (sc.hasNextLine()) {
    String line = sc.nextLine();
    if (line != null && !line.equals("")) {
        String[] row = line.split(";");
        dtm.addRow(row);
    }
}

Known issues

    
Problems and bugs I left in

    
I closed the project with these still in the code. Just like my other coursework archives, they are documented here as they were submitted rather than patched afterwards.

    
Bugs

    
    
      
  • Any non-empty login succeeds. In frmLogin.java, the while loop reads src/user.txt and breaks when the username and password match, but never sets a boolean flag. When the loop finishes after reaching the end of the file, the code still shows "Login successful!" and opens DiceRollMain.
    • 
      
  • Every roll is logged as "user". Because Account and interfaceInfo sit in Java's unnamed default package, classes inside package Main cannot import them. As a workaround, OneDie, TwoDice, and HigherDice hardcode String username = "user";, and frmLogin never stores displayNameFromFile into acc.
    • 
      
  • The Exit button quits the whole app instead of returning to Login. DiceRollMain.java still has a teammate comment (//TEMP รบกวนเขีบนโต้ดกลับเข้าหน้าล็อกอินด้วย — "please write code to go back to the login page") above System.exit(0);, blocked by the same default-package import rule that prevented Main from referencing frmLogin.
    • 
      
  • Registration allows duplicate usernames. frmRegister.java reads user.txt to calculate nextId, but doesn't check whether the chosen username already exists—which is why 123 and 22 appear twice in user.txt.
    • 
    

    
Other quirks

    
    
      
  • Leftover classes in src/. tblUser.java is a complete user-list window with a working LOGOUT button that nothing opens, and PersonLog.java is commented out from top to bottom.
    • 
      
  • Editable history cells rewrite the log on close. Unlike tblUser, History.java leaves JTable cells editable and rewrites HistoryLog.txt from the table model inside formWindowClosing.
    • 
      
  • Plain-text passwords and delimiter splitting. Passwords are stored unhashed in user.txt, and typing a comma in registration or a semicolon in a log field would split into extra columns.
    • 
      
  • JDK 8 internal header renderer and relative paths. History.java imports sun.swing.table.DefaultTableCellHeaderRenderer (which requires --add-exports on JDK 9+), and paths like "src/user.txt" assume the working directory is the project root.
    •
